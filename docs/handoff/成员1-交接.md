## 3. 怎么跑

```powershell
# 仓库根目录
python -m http.server 8010 --bind 127.0.0.1
# 打开 http://127.0.0.1:8010/frontend/
```

页面走的就是真实交互：载入样例 → 检查缺口 → 确认规格 → 生成计划（离线规则模式）→ 校验 → 编排 → 确认版本 → 导出 JSON。
点顶部“确认版本”后再次编辑任意任务，会看到“确认版保持只读，已派生新草稿”。

单元测试（Node 22+）：

```powershell
node frontend/tests/reducer.test.mjs
node frontend/tests/gapCheck.test.mjs
node frontend/tests/canvasLinking.test.mjs
node frontend/tests/schedule.test.mjs
node frontend/tests/views.smoke.test.mjs
node tests/demo.test.mjs
```

当前实际结果：8 + 5 + 4 + 8 + 5 + 3 = **33 项全部通过**。

接真实后端时把入口换成 `http://127.0.0.1:8010/frontend/?api=http`，只改 `api.js` 的 `base` 与服务端前缀即可。

## 6. 给其他成员的交接件

**给成员 3（契约与校验）**

- 工作台消费的字段形状见 `docs/frontend-api-contract.md` 第 3 节，`frontend/fixtures/*.json` 是同一套字段的样例。请以 `backend/app/contracts` 为准，逐项确认或改写；我这边改字段只需要动 fixture 和 `precheck.js` 的字段名。
- `precheck.js` 的九类问题码（`DUPLICATE_TASK_ID`、`MISSING_DEPENDENCY`、`SELF_DEPENDENCY`、`DEPENDENCY_CYCLE`、`MISSING_ACCEPTANCE`、`UNRESOLVED_INPUT`、`UNRESOLVED_DESIGN_REF`、`REQUIREMENT_WITHOUT_IMPLEMENTATION`、`REQUIREMENT_WITHOUT_VERIFICATION`）建议与你的 `ValidationReport.code` 对齐，否则界面要维护两套映射。

**给成员 5（API 与存储）**

- `docs/frontend-api-contract.md` 里的十一个接口就是前端全部依赖；`api.js` 的 `createHttpApi()` 已按这些路径写好，可直接对照实现。

**给成员 6（可视化与集成）**

- 共享状态在 `frontend/src/shared/reducer.js`：`selectedTaskId`、`plan.plan_id`、`plan.revision`、`execution`。图表联动请订阅同一 store，不要另存业务副本。

**给成员 2（PM 生成）**
