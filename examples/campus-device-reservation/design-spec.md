# 校园实验设备预约与借还平台 MVP

文档编号：SPEC-CAMPUS-DEVICE
版本：v1.0
用途：Lab2 可重复的 DeepSeek 实时验收输入。
范围：校内设备预约、管理员交接和借还记录。
本规格描述目标产品，测试工作流时不需要连接学校服务或真实用户数据。

## 产品范围

面向校园实验室的学生与管理员，提供校内网页端设备查询、预约、借出与归还。
首期覆盖一个校区和一套设备台账。用户使用现有校内登录会话；系统维护预约和借还状态。
核心目标是减少重复预约、记录设备在何时交由谁保管，并让状态变化可追溯。

- 学生可查询设备、选择可用时段、提交或取消自己的预约。
- 管理员可确认借出和归还，并记录必要的交接结果。
- 已登录用户可查看自己的记录，管理员可按授权范围查看状态。
- 冲突、权限或异常请求给出明确反馈，失败不改变设备状态。

明确排除：

- 不做支付、押金和财务结算。
- 不做跨校区调拨与校外账号。
- 不自建账号密码体系；不接入真实短信。
- 不做候补、自动续借、复杂报表、推荐算法和设备远程控制。
- 不处理硬件诊断，只记录管理员勾选的验收结果。

## 需求条目

| 编号 | 行为描述 | 验收条件 |
| --- | --- | --- |
| REQ-DEV-01 | 学生按设备类别和时间查询可用设备 | 半开区间 [开始, 结束) 判断重叠；损坏、停用或所选时段已预约的设备不显示为可用；输入时段无效时提示且不请求。 |
| REQ-DEV-02 | 学生为单台设备创建预约 | 只有已登录学生可以创建；开始时间早于结束且不早于当前时间；同一设备两个重叠提交至多一个成功，另一个返回 409；操作失败不写入新的有效预约。 |
| REQ-DEV-03 | 学生取消自己的预约 | 只有本人且处于已预约状态才可取消；取消后时段重新可用；仍使用相同请求 ID 重试时返回原结果，不重复写操作记录。 |
| REQ-DEV-04 | 管理员确认现场借出 | 只有有设备管理权限的管理员可借出；只处理处于已预约状态的记录；超出预约开始前 15 分钟至开始后 30 分钟窗口时拒绝；重复提交不产生多条借出事件。 |
| REQ-DEV-05 | 管理员确认归还并记录交接结论 | 只处理已借出记录；归还结论为正常或异常；异常必须填写理由，设备立即进入待维护；普通学生不能执行归还。 |
| REQ-DEV-06 | 用户查看借还状态及自己的历史 | 学生只可查看自己的预约；管理员按校内授权范围筛选；列表显示已预约、已取消、已借出、已归还；详情可以看到本人或授权范围内的必要时间戳。 |

## 约束

- 后端优先使用 Python，浏览器为普通校园网页；SQLite 支持首期原型。
- 时间戳在持久层使用 UTC；界面显示 Asia/Shanghai。
- 创建预约、取消、借出、归还各使用独立事务。
- 请求 ID 仅在同一主体和同一操作内判重，不跨主体泄露结果。
- 日志不保存登录凭据；用户标识仅用于授权与追溯。
- 不假定真实校务认证接口可用，演示使用明确标记的测试账号。
- 不允许因任意错误把所有失败改为 200；失败后保留原状态。
- 键盘可达的说明和错误提示不得只依赖颜色。

## 详细规则与验收推演

### 01 · 查询与筛选

- 查询默认只显示在选定时段可用且未停用的设备。
- 先读取类别，再选择开始、结束时间。
- 类别仅使用当前台账中已启用的选项。
- 当用户改动任意时间字段，旧结果可暂留但显示待刷新。
- 搜索提交前检查开始时间与结束时间。
- 结束时间与开始时间相等时拒绝。
- 没有设备满足条件时展示无结果提示。
- 网络失败可重试，筛选条件保持。
- 预约结束点与下一预约开始点相同不视为重叠。
- 任一设备有重叠预约时不标为可用。
- 停用、损坏、待维护的设备不标为可用。
- 排序按设备名称，然后按设备 ID 稳定排序。

### 02 · 预约与并发

- 用户在设备详情确认设备和时段后提交。
- 服务器检查设备存在、可预约以及会话有效。
- 同一个设备只执行一次共享的冲突判定。
- 读取冲突和写记录必须在同一事务完成。
- 重叠判定：已有开始小于新结束，且新开始小于已有结束。
- 预约状态为已取消的记录不阻塞未来查询。
- 在当前时刻之前开始的请求被拒绝。
- 页面提交期间禁止重复触发。
- 服务器仍须处理浏览器以外的并发请求。
- 返回成功后显示预约编号、设备名和已选时段。
- 返回冲突后保留输入，让学生改选时间。
- 取消或失败的申请不得新增有效预约。

### 03 · 取消

- 已预约的记录允许预约人取消。
- 非预约人不能取消。
- 已借出、已归还记录不可使用取消动作。
- 同一个请求 ID 重试不新增取消事件。
- 不同的请求 ID 如果重复取消，返回当前状态或明确冲突。
- 取消生效时间以服务端记录为准。
- 取消提交成功后重新查询应能看到释放后的时段。
- 已完成的取消不能通过浏览器撤销按钮恢复。
- 页面必须用文字确认取消结果。
- 状态变更历史不得因取消成功而删除。
- 学生快速点击两次只展示一个最终状态。
- 权限错误不返回其他用户的预约细节。

### 04 · 借出

- 管理员用预约编号定位操作对象。
- 系统核对管理员与设备所在范围的权限。
- 借出前展示设备标识、预约状态与时间范围。
- 允许开始前 15 分钟至开始后 30 分钟处理。
- 正好处于窗口边界时允许处理。
- 已取消、已借出或已归还记录不允许再借出。
- 成功记录操作人、时间和预约版本。
- 失败保留原状态并给出原因。
- 同一个请求 ID 不产生重复借出事件。
- 借出结果供归还模块读取。
- 此流程不要求读取设备传感器。
- 发生共享状态冲突时，刷新页面加载最新状态。

### 05 · 归还与异常

- 归还只适用于已借出的记录。
- 管理员选择正常或异常。
- 异常原因去掉首尾空白后不得为空。
- 归还状态与是否进入待维护在同一事务更新。
- 正常归还不改变设备可借策略。
- 异常设备在待维护期间不可被查询为可用。
- 学生端只显示与其记录相关的状态和必要时间。
- 异常原因应可供授权管理员复核。
- 表单失败时保留管理员已录入的原因。
- 已归还记录不重复生成归还事件。
- 不包含自动维修或诊断。
- 硬件检查由现场管理员完成。

### 06 · 历史与可见性

- 无会话时不展示历史。
- 学生只查询自身记录。
- 管理员按授权实验室范围查询。
- 状态筛选使用同一套枚举。
- 默认按最近一次状态更新时间倒序，同一时间按记录 ID 排序。
- 详情展示预约时间、借出时间和归还时间中已存在的项。
- 不需要展示内部事务、数据库账号或会话标识。
- 不存在的记录与不可见记录按统一产品策略处理。
- 空列表有可理解的提示文本。
- 状态必须有文字标签，不依赖单一颜色。
- 历史页不提供批量修改功能。
- 分页大小默认 20，首期不做自定义导出。

## 页面与交互补充

- 列表行显示设备名、实验室、类别和可用状态。
- 查询结果的设备图片不是必填交付物。
- 预约确认窗显示时段并提供返回修改选项。
- 操作按钮禁用时显示禁用理由。
- 加载提示与错误提示使用辅助技术可读的状态标记。
- 冲突提示说明预约没有建立。
- 管理员页面的借出和归还使用文字区分。
- 异常归还后显示维护标记。
- 历史筛选清空后回到默认状态。
- 登录失效后返回登录，不重发正在提交的操作。

## 数据一致性补充

- 设备 ID 和预约 ID 各自唯一。
- 台账名称可编辑，历史记录仍引用稳定 ID。
- 预约记录保存时间区间和状态。
- 交接事件引用预约 ID、操作类型、来源和时间。
- 状态更新按预约版本判断，避免覆盖其他管理员刚保存的结果。
- 取回重复请求结果时校验主体和操作类型。
- 写事务失败时事件和主记录一起回滚。
- 操作成功后可用于独立测试的证据包括状态、时间和一条对应事件。
- 测试案例可以使用时钟注入，避免依赖实际时刻。

## 错误口径

- 400：请求格式无法解析。
- 401：无有效会话。
- 403：角色没有当前操作权限。
- 404：目标不存在或无法按读取策略暴露。
- 409：时段冲突、状态竞争或版本冲突。
- 422：字段合法性、窗口或业务条件不满足。
- 失败响应不返回其他成员的敏感信息。
- 客户端使用自己的错误文案，不直接展示数据库消息。

## 测试数据和交付约定

- 至少准备两台模拟设备，其中一台可切换为待维护。
- 至少准备两个测试学生和两个授权范围不同的管理员会话。
- 使用固定时钟验证借出窗口与重叠边界。
- 并发预约用例必须验证落库的有效记录数。
- 幂等用例须检查最终响应和操作事件数。
- 接口与页面验收都要保留需求编号。
- 发布前复查模拟身份不会在正式运行中成为默认用户。
- Demo 不使用真实学工号或个人资料。

## 仍需人工确认的事项

- 校方正式登录对接方式留待正式项目决定，原型不外接。
- 待维护设备如何恢复可用由后续维护模块规定，首期不提供恢复页面。
- 留存周期由校方确认，首期原型不做自动清理。
- 上述待定事项不授权 AI 擅自扩大范围。
