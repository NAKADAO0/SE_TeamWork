# 校园失物招领 MVP · 现场设计规格（第三类产品）

用途：跨产品通用性验收（V02、V12）的第三类规格，不属于聊天或内容社区两个预置案例。
输入形式故意用 Markdown，用来同时验证文本标准化路径。

## 1. 产品范围

面向本校师生，提供失物登记的发布、按条件查找、认领申请与状态跟踪。
首期只做单校区、实名登录后的网页端。

明确排除：

- 不做即时聊天或私信，认领沟通通过电话由失主自选是否公开
- 不做支付、悬赏与运费
- 不做跨校区与校外用户
- 不做图片自动识别，图片只作为附件

## 2. 需求条目

| 编号 | 行为描述 | 验收条件 |
| --- | --- | --- |
| R-LF-01 | 登录用户发布失物或拾物登记，必填标题、地点、时间、联系方式 | 提交后生成唯一登记编号，列表可查到该编号 |
| R-LF-02 | 按关键字、地点与时间段筛选登记 | 组合筛选结果满足全部条件，清空条件回到全量列表 |
| R-LF-03 | 失主对某条登记发起认领申请，并附证明材料 | 同一用户对同一条登记的重复申请被拒绝，返回 409 |
| R-LF-04 | 发布者处理认领申请（同意、拒绝）并关闭登记 | 关闭后登记不可再被申请，列表显示已关闭 |

## 3. 模块

| 编号 | 名称 | 职责 | 关联需求 |
| --- | --- | --- | --- |
| M-LF-ITEM | 登记模块 | 发布、编辑、关闭登记，维护唯一编号 | R-LF-01、R-LF-04 |
| M-LF-SEARCH | 检索模块 | 关键字、地点、时间段筛选与排序 | R-LF-02 |
| M-LF-CLAIM | 认领模块 | 申请、证明附件、状态流转与幂等 | R-LF-03、R-LF-04 |
| M-LF-WEB | 页面 | 列表、详情、发布表单与认领入口 | 全部 |

## 4. 设计条目

- I-LF-PUBLISH：`POST /items` 发布登记，返回 `item_id`
- I-LF-SEARCH：`GET /items?q=&place=&from=&to=` 组合筛选
- I-LF-CLAIM：`POST /items/{id}/claims` 认领申请
- I-ERR：错误码统一为 400、403、404、409、422
- I-CONSIST：同一登记的认领申请在同一事务内判重

## 5. 约束

- 技术栈：Python 3.12 + SQLite，前端原生 ES Module
- 平台：校内网网页端，移动端只保证可读
- 数据：附件不超过 5 MB，只存本地路径
- 已有设施：复用学校统一登录会话，不新建账号体系

## 6. 现场扰动检查

1. 只把产品名改成别的名字，不应新增任何功能任务。
2. 新增一条“逾期 30 天自动关闭”的需求，应出现对应实现与验证任务，并触发覆盖检查更新。
3. 删除 R-LF-03 的验证任务后，校验器必须报出 `REQUIREMENT_WITHOUT_VERIFICATION`。
